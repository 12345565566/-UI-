**PlaceNear(main)：贴边算法**（`:109-130`）

1. 取主窗所在屏幕的 `WorkingArea`；
2. 默认 y = `main.Top + 40`；
3. 优先放主窗**右侧**：若 `main.Right + 12 + Width <= s.Right` → x = `main.Right + 12`；
4. 否则放**左侧**：若 `main.Left - 12 - Width >= s.Left` → x = `main.Left - 12 - Width`；
5. 两侧都放不下 → 放**下方**：x 夹到 `min(main.Right - Width - 12, s.Right - Width - 8)`，y = `main.Bottom + 8`；若超出屏幕底则 y = `s.Top + 20`；
6. 最后统一夹回工作区（x、y 各夹一次）。
7. `MainForm` 在 `Move` 事件里再次调用 `PlaceNear`，所以拖主窗时苏苏跟着走（`MainForm.cs:152`）。

## 1.4 对话状态机

```
StartAt(nodeId)                       :100-107
  ├ 清 history、Skipped=false、停两个 Timer
  └ GotoNode(nodeId)
GotoNode(id)                          :143-152
  ├ id == "diag" → SusuDiag.BuildNode(Ctx, St)   ← 唯一一个走运行时的 id
  ├ 其它 → GuideScript.Get(id)；取不到 → Close2()

  └ ShowLine()
ShowLine()                            :228-242
  ├ SusuVoice.Play(line)              ← 只有 Who=="苏苏" 且有音频才响
  ├ SetPic(line.Pic)
  ├ _full = line.Text；_shown = ""；_typing = true；启动 _typeTimer
  └ history 追加 "苏苏：xxx"（有 Who）或 "· xxx"（无 Who）
TickType()                            :244-251
  └ 每 26ms 多吐 2 个字；吐完 → ArmAuto()
Advance()                             :273-282
  ├ 打字中 → 立刻全文显示（不推进）
  ├ _choicesShown → 直接 return
  └ _lineIdx++；越界 → ShowChoices()
ShowChoices()                         :284-307
  ├ 有选项 → SusuChoiceForm 模态弹窗
  │    PickedAction 非空 → DoAction(action, Picked.next)
  │    Picked 非空       → GotoNode(Picked)
  │    Dismissed        → Close2()
  └ 无选项 → Next 为空则 Close2()，否则 GotoNode(Next)
```

**关键细节**：`Close2()` 是 `Hide()` 而不是 `Close()`，且**必须手动 `SusuVoice.Stop()`**——源码注释写明「Hide() 不会触发 OnFormClosed，这里必须自己停，否则下次同一句会被吞」（`:381-392`）。`ClosedByUser` 事件用来让主窗刷新「呼叫苏苏」按钮。

## 5.6 播放链路（`Play` / `PlayFile`，`:209-252`）

```
Play(GuideLine ln)
 ├ Muted || ln == null → return
 ├ ln.Who != "苏苏" → return            ← 旁白不发音
 ├ _map 里按 ln.Text 查 → 查不到 Log.Warn("配音缺失（这句没有对应音频）") 后 return
 └ PlayFile(file)
      ├ 内嵌：GetManifestResourceStream("Zogos.Voice." + file) 读成 byte[]
      ├ 外部：File.ReadAllBytes(_dir + file)
      ├ data.Length < 44 → return
      ├ Stop()（先停旧的）
      ├ _lastDurationMs = WavDurationMs(data)
      ├ _stream = new MemoryStream(data); _player = new SoundPlayer(_stream); _player.Play()
      └ _playing = file
```

- 用 `System.Media.SoundPlayer`（只支持 WAV/PCM），**非阻塞** `Play()`。
- 时长自己解析 WAV 头（`WavDurationMs`，`:266-297`）：校验 `RIFF` → 走 chunk 找 `fmt `（channels/rate/bits）与 `data`（size）→ `dataSize * 1000 / (channels*rate*bits/8)`。解析失败返回 0，`ArmAuto` 就退回 2 秒。
- 诊断用只读属性：`Available` / `Count` / `Has(text)` / `LastPlayLoaded` / `LastDurationMs` / `RemainingMs`（`:88-121`）。

# 七、AI 诊断

## 7.1 `AiClient`：协议与请求体

**OpenAI 兼容**（源码注释：「只要是兼容 OpenAI 的服务（官方 / 中转 / 本地 ollama / LM Studio）都能用」，`AiClient.cs:12-13`）。

- `Normalize(baseUrl)`：`Trim()` → 去尾部 `/` → 若以 `/chat/completions` 结尾则再砍掉（`:17-23`）。所以用户填 `https://api.openai.com/v1` 或完整 URL 都行。
- 两个端点：`GET {base}/models`（`:98-130`）、`POST {base}/chat/completions`（`:133-167`）。
- 请求头：`Content-Type: application/json`、`User-Agent: ZOGOS-Launcher/{Log.Version}`、有 key 时 `Authorization: Bearer {key}`（`:32-36`）。
- 请求体（`:147-151`）：

```json
{
  "model": "<st.ApiModel>",
  "temperature": 0.3,
  "stream": false,
  "messages": [
    { "role": "system", "content": "<SystemPrompt()>" },
    { "role": "user",   "content": "<BuildUserPrompt()>" }
  ]
}
```

- 序列化用 `System.Web.Script.Serialization.JavaScriptSerializer`，`MaxJsonLength = 16 MB`（模型列表 8 MB）。
- **容错**：即使 `stream=false`，`ExtractChatContent` 也会尝试解析 `data:` 流式分片、`choices[].message.content`、`choices[].delta.content`、`choices[].text`，以及 content 为数组（多模态）时的 `text`/`content` 字段（`:169-269`）。这是为了兼容各种中转站的返回差异。
- 错误处理：`WebException` 时把响应体读出来作为 `HTTP 错误：{body}`（`:46-62`）；`Chat` 拿不到内容时把前 600 字回显（`:163`）。
- 超时：模型列表 20 s；对话由调用方给（苏苏 AI 诊断 **90 s**，`SusuWindow.cs:200`；关键词翻译 30 s，`WorkshopClient.cs:114`）。

## 7.2 `SystemPrompt()` 原文（`:272-293`）

> 你是 RimWorld（边缘世界）整合包的技术支持助手，服务对象是不太懂电脑的普通玩家。
> 回答要求：
> 1. 用简体中文，大白话，别堆术语；总长度控制在 300 字以内。
> 2. 先给一句「结论」，再给 2~4 条按优先级排序的处理步骤，每条不超过两行。
> 3. 不要重复用户已知的信息，不要编造日志里没有的东西。
>
> 【这个整合包已知的坑（务必优先考虑）】
> - RimWorld 1.7 换了新引擎，没有做显存不够的保护：核显或显存小于 4G 的电脑会爆显存，表现为黑屏闪退，退出码常见 0xC0000005（-1073741819）。解法是打 Steam 创意工坊的「1.7 显存分配补丁」；但大显存用户打这个补丁是负提升，不要推荐他们装。
> - 整合包路径不能含中文，否则模组加载不出来。
> - 启动器只在第一次或整合包更新时完整替换 Config，之后只更新排序；Prefs.xml（画面/音量）和 KeyPrefs.xml（按键）是玩家私有的，不会被覆盖。
> - 本地模组索引为 0、或模组全缺失，说明整合包没解压完整（可能只解压了一层）。
> - 退出码 0xC0000135/0xC000007B 多是缺运行库或位数不对；0xE0434352 是模组抛异常。
>
> 如果日志里看不出明确原因，就说明「日志里没有直接证据」，然后给出最可能的 2 个怀疑方向和处理办法。

## 8.3 `WorkshopClient`（网页 / 翻译 / 本地检索 / 后端选择）

**网页抓取搜索**（`Search`，`:34-53`）
URL：`https://steamcommunity.com/workshop/browse/?appid=294100&searchtext={q}&browsesort=textsearch&section={readytouseitems|collections}&actualsort=textsearch&p=1[&requiredtags[]={version}]`。

**HTML 抠 JSON**（`ParseHtml`，`:55-95`）——Steam 把结果塞在 JS 字符串里，所以：
1. 先 `\"" → "` 、`"\\\\" → "\\"` 还原转义；
2. 正则 `"publishedfileid":"(\d+)"` 找所有 id 的**起始下标**，把相邻两个 id 之间的片段当一个条目（最后一个截 20000 字）；

4. `WebUtility.HtmlDecode(Unescape(x))` 清理；`seen` 去重；**最多 30 条**；
5. 一条都没解析到 → `err = "搜索页打开了，但没有解析到模组。Steam 页面结构可能变了。"`

**中文 → 英文关键词**（`TranslateQuery`，`:97-130`）
- 没有中文 → 原样返回；

**工坊目录探测**（`FindWorkshopContentDir`，`:174-210`）：注册表 `HKCU\Software\Valve\Steam:SteamPath`、`HKLM\SOFTWARE\WOW6432Node\Valve\Steam:InstallPath`、`ProgramFilesX86\Steam`、`D:\Steam`、`D:\steam`，逐个拼 `steamapps\workshop\content\294100`，返回第一个存在的。

**按 id 下载并复制进 Mods**（`DownloadToPack`，`:212-258`）

3. `FileOps.CopyTree` 复制到 `{ModsDir}\{源目录名}`（已存在先 `ClearDir`）；
4. 合集多等 4 s 再收工；
5. 超时 → 「Steam 下载超时，或该合集没有可复制的模组。请确认 Steam 已登录并完成订阅。」

**离线本地检索**（`LocalSearch`，`:309-369`）

2. 否则/失败 → 走网页抓取（需要梯子）；

## 9.3 `Plan`：同步计划与匹配算法（`WorkshopSync.cs:318-383`）

输入：工坊缓存目录、本地 Mods 目录、`replaceExisting`。输出 `SyncReport`。

1. 两个目录各 `ScanRoot` 一次（`wsp` / `local`），并把结果灌进 `ModIdIndex`；
2. 建两张本地索引：`localByPkg`（packageId → 条目）、`localByPub`（publishedFileId → 条目），**先到先得**；
3. 逐条遍历**工坊**条目，判定：

| 条件 | `Action` | `TargetDir` | `Reason` |
|---|---|---|---|
| `!havePkg && !havePub` | 「复制」 | `{modsDir}\{工坊目录名}` | 空 |
| 已有，且勾了「本地已有也覆盖」 | 「覆盖」 | `havePub ? localByPub[pub].Dir : localByPkg[pkg].Dir` | 「本地已有同一 PublishedFileId，按源覆盖」/「本地已有同一 packageId（folder 名不同），按源覆盖」 |
| 已有，未勾覆盖 | 「跳过」 | 同上 | 「本地已有」 |

4. 工坊目录里一个都解析不出来 → `Errors.Add("工坊目录里没有解析到任何带 About.xml 的模组。")`；
5. 目录不存在 → 分别给「没有找到 Steam 创意工坊下载目录（steamapps\workshop\content\294100）。」/「没有找到本地 Mods 目录：{dir}」。

**匹配键的设计要点**：同时用 `packageId` 和 `publishedFileId` 两条线——`packageId` 能认出「同一个模组换了文件夹名」，`publishedFileId` 能认出「本地是工坊 id 目录、工坊是另一种目录结构」。

## 9.4 `Apply`：执行（`:386-425`）

6. 收尾日志「工坊同步完成：{Summary}」。

## 11.1 `PdfDoc`：极简 PDF 写入器（`PdfDoc.cs`）

- **每页就是一张 JPEG**：`AddPage(bmp, quality)` 用 JPEG 编码器把整页压进内存（`:23-37`）；
- A4 尺寸常量 `PW = 595.276, PH = 841.89`（`:16`），页面 `/MediaBox [0 0 595.276 841.89]`；
- 对象排布：1=CataLog，2=Pages，之后每页 3 个对象（Page / XObject 图像 / Content 流），xref 手写（`:52-103`）；
- 图像用 `/Filter /DCTDecode`（即 JPEG 直塞），内容流只有一句 `q {PW} 0 0 {PH} 0 0 cm /Im0 Do Q`（铺满整页）；

## 12.3 重打包流程（`Run`，`:132-251`）

1. 判定源是目录还是 zip；
2. 顶层名：`TopFolder` → 否则源目录名 → 否则 zip 文件名去扩展；`Safe()` 过滤非法文件名字符、截 60 字（`:424-437`）；
3. 源是 zip 时先算「公共前缀」（第一个 entry 的第一个 `/` 之前的部分），复制时剥掉，避免出现双层目录（`:156-163`）；
4. 删除同名输出文件；`ZipArchive(ZipArchiveMode.Create)`；
5. **目录源**：`Collect` 递归收集 → 逐个 `CreateEntryFromFile(CompressionLevel.Optimal)`；每 40 个回调一次 `progress(rel, n)`；计数模组靠 `Mods` 下的一级目录名；
6. **zip 源**：遍历 entry，**先把 `\` 统一成 `/`**（注释：Windows 打的 zip 用反斜杠，不统一会让过滤规则失效、安卓侧也解不开），剥前缀，`Want(rel,o)` 过滤，流式 `CopyTo`；
7. 若 `IncludeCjk` → `InjectCjk`；
8. 填 `FileCount / Bytes / ModCount / Seconds / Note`。

**中文字体注入**（`InjectCjk`，`:259-318`）：
1. 打开输出 zip（`ZipArchiveMode.Update`），找 `Config/ModsConfig.xml`；
2. 找到就删掉后重写（先把原文读进内存）；找不到则新建一份骨架 XML；
3. `EnableMod(cfg, "rimdroid.cjkfont")`：已含该 id 则不动，否则插到 `<activeMods>` 之后的第一行（`:321-330`）；
4. 把 CJK zip 里所有 entry 写到 `{prefix}Mods/{entry}`；

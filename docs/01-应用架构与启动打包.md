# 01 · 应用架构、启动流程与打包链路

> 对象：`<工作区>\源码`（命名空间 `Zogos`，C# / WinForms / .NET Framework 4.x，手工 `csc` 编译）。
> 目的：给「用新技术栈重写前端 UI」的人提供外壳、进程、配置、打包层面的准确事实。
> 约定：结论后标 `文件:行号`；读不到或无法确认的写「未确认」。

## 0. 一句话架构

单进程 WinForms 应用，无框架、无 DI、无 XAML；所有 UI 由 `Control` 子类手绘（`OnPaint`）+ 绝对坐标布局（`Bounds = new Rectangle(...)`）构成。启动时先做「整合包目录识别」，把结果塞进 `PackContext` 与 `Settings`，然后只创建一个 `MainForm` 并 `Application.Run`（`源码\Program.cs:102-103`）。另有三个独立可执行入口：CLI（`Zogos.CliMain`）、安装包（`Zogos.SetupMain`）、手机版导出工具（`Zogos.MobileExportMain`）。

关键命名不一致（重写时不要再沿用）：exe 名用 **Astra**（`Astra创世神协议.exe`），数据目录用 **ZOGOS**（`%LocalAppData%\ZOGOS创世神启动器`，`源码\Program.cs:114-117`），窗口标题普通版为 `Astra创世神协议`（`源码\Edition.cs:12`），而 `Edition.cs` 顶部注释仍写「ZOGOS创世神启动器」（注释已过时，`源码\Edition.cs:7`）。

## 1. 程序入口与启动链

### 1.1 `Main` 执行顺序

`源码\Program.cs:15-104`：

| # | 动作 | 代码位置 | 要点 |
|---|------|----------|------|

| 6 | 应用主题 | `Program.cs:36` | `Pal.ApplyTheme(Edition.Sponsor ? st.ThemeIndex : 0)`：**普通版强制主题 0** |
| 7 | `PackContext.Detect(...)` | `Program.cs:37` | 目录识别，见 3 |

| 11 | 找不到 `RimWorldWin64.exe` 时弹窗让玩家手选目录 | `Program.cs:57-82` | `--shot`/`--smoke` 模式跳过此步 |

### 1.2 命令行参数（GUI 版）

| 参数 | 变量 | 语义 | 引用 |
|------|------|------|------|
| `--root <目录>` | `rootOverride` | 手动指定整合包根目录；**优先级最高**，先取「像整合包」的候选，否则回落到自动识别 | `Program.cs:26`、`Core4.cs:281-297` |
| `--target <目录>` | `targetOverride` | 直接指定要写入的 `Config` 目录（游戏 `-savedatafolder` 的上一级由它反推） | `Program.cs:27`、`Core.cs:529` |
| `--appdata <目录>` | `appData` | 覆盖设置 / 日志 / 备份目录（默认 LocalAppData 下的 `ZOGOS创世神启动器`） | `Program.cs:28`、`Core.cs:575-580` |
| `--shot <目录>` | `shotDir` | 逐页渲染 PNG + 导出 `layout.txt`，用于自动检查界面 | `Program.cs:29`、`296-388` |
| `--susu <目录>` | `susuDir` | 把「苏苏」窗在 6 个对话节点上离屏渲染成 PNG | `Program.cs:30`、`121-150` |
| `--smoke <目录>` | `smokeDir` | 无窗口自检：构造 MainForm → 反射调 `OnLoaded` → 逐页 `SwitchPage` → 导控件树/重叠检测 → 写 `layout_all.txt` | `Program.cs:31`、`152-293` |

参数解析细节：`--root` 等只有在「后面还有一个参数」时才消费（`Program.cs:26-31`），所以把 `--shot` 放在命令末尾会静默失效。`--susu/--smoke/--shot` 的优先级顺序是固定代码顺序（`Program.cs:84-100`），三者同时给时只有 `--susu` 生效。

`Program.cs:75-76` 把手选目录同时赋给局部变量 `rootOverride` 和静态字段 `p_rootOverride`，但 `p_rootOverride`（`Program.cs:112`）从未被读取——死代码。

### 1.3 启动链里的隐藏依赖

- 主题必须在构造任何控件前应用（`Program.cs:36` 早于 `MainForm`），否则 `Pal.*` 静态色值取默认（`Widgets.cs:15-33`）。
- 日志在 `PackContext.Detect` 之后初始化（`Program.cs:38`），因此 Detect 过程中的 `Log.Warn`（如 `Core.cs:421`）会写进默认（空）日志路径，可能丢失。属于已知缺陷。
- `MainForm` 构造时会再读一次 `Pal` 当前值并 `RebuildUi`（`MainForm.cs:126`、`2295-2302`），重写时主题应是「可注入的运行时状态」而非全局静态。

## 2. 两版 Edition（SPONSOR 编译开关）

### 2.1 机制

`Edition.cs` 用预处理器条件编译，`/define:SPONSOR` 打开赞助版（`源码\Edition.cs:15-23`）。**两版是同一份源码编出的两个 exe**，不是运行期开关；`Edition.Sponsor` 是 `const bool`，编译器会做常量折叠（`Edition.cs:16`、`20`）。

|------|----------------|------------------------------|------|
| `Edition.Sponsor` | `false` | `true` | `Edition.cs:15-23` |
| `Edition.Name` | `普通版` | `赞助版` | `Edition.cs:17`、`21` |

`Pal` 是**全局静态色板**，`ApplyTheme(idx)` 一次性改 `Accent / AccentDeep / CardBorder` 三个霓虹色，其余暗色底固定（`Widgets.cs:40-68`）。

| 1 | 霓虹紫 | `(190,80,255)` | `(120,50,230)` | `Widgets.cs:56-59` |

切换主题会 `Save()` 后 `RebuildUi()`（`MainForm.cs:2295-2302`），不需要重启；外观页另有「重启启动器」按钮，`Process.Start` 自身后 `Close()`（`MainForm.cs:2597-2608`）。主题索引上限在读取时被 `Math.Max(0, Math.Min(3, …))` 夹住（`MainForm.cs:2290`）。

## 3. 运行环境识别（PackContext / Settings）

### 3.1 候选目录来源与优先级

`PackDetector.ResolveRoot`（`源码\Core4.cs:274-366`）：

| 顺序 | 来源 | 代码 |
|------|------|------|
| 0 | `--root` 指定值本身、其 `\RimWorld` 子目录、其父目录；命中 `Strict` 立即返回，否则清空重来 | `Core4.cs:281-297` |
| 1 | 启动器所在目录及其**直接子目录** | `Core4.cs:303`、`263-272` |
| 2 | 启动器父目录及其直接子目录 | `Core4.cs:305` |
| 3 | 启动器祖父目录（不加子目录） | `Core4.cs:307` |
| 4 | `settings.ini` 里上次的 `Root` | `Core4.cs:309` |

候选上限 600 个目录（`Core4.cs:170`、`243`）。筛选规则：

1. 先只保留 `Strict == true` 的候选；一个都没有才退回全部候选（`Core4.cs:318-320`）。
2. `settings.PackId` 与候选的识别令牌 `packId` 相同 → 直接采用（`Core4.cs:322-334`）。
3. 否则排序：`Dir == launcherDir` 优先 → 分数降序 → 路径短优先（`Core4.cs:337-344`），取第一个（`Core4.cs:365`）。

### 3.2 打分规则（`PackDetector.Score`，`Core4.cs:172-228`）

| 特征 | 加分 | 备注 |
|------|------|------|
| 存在识别令牌（`ZOGOS整合包标识.json` 或 `zogos.pack`） | +100 | `Core4.cs:181-186` |
| `RimWorld\RimWorldWin64.exe` 或 `RimWorld\RimWorld.exe` | +40 | `Core4.cs:188-195` |
| `Config\ModsConfig.xml` | +30 | `Core4.cs:200-201` |
| 仅存在 `Config` 目录 | +10 | `Core4.cs:202` |
| `排序文件` 下有 `*.xml`/`*.json` | +25 | 空文件夹 +8（`Core4.cs:206-217`） |
| `RimWorld\Mods` 目录 | +15 | `Core4.cs:221` |
| `RimWorld\Version.txt` | +5 | `Core4.cs:222` |

`Strict = hasExe && (hasCfg || sortN > 0)`（`Core4.cs:226`）——「像整合包」的判定只看这三类特征。

### 3.3 识别令牌

`PackMarker` 在整合包根目录写两个文件：`ZOGOS整合包标识.json` 与 `zogos.pack`（`Core4.cs:16-17`、`130-132`）。JSON 含 `packId / packName / updatedAt / game / configDir / sortDir / gameVersion / sortScheme / modCount / launcher`（`Core4.cs:112-130`）。`packId` 为 12 位 GUID 片段（`Core4.cs:84-87`）；目录改名/搬家后靠它认包。Detect 时若已满足 `hasExe && (hasCfg || hasSort)` 且无令牌，会**自动写入**令牌（`Core.cs:621-631`）。

## 4. 编译与打包链路

### 4.1 工具链（无 MSBuild / 无 NuGet）

`csc.exe` 来自 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319`，不存在则退回 32 位目录（`打包两版.bat:10-12`）。统一参数：`/nologo /codepage:65001`，所有 `.cs` 直接作为源文件列表传入，资源用 `/resource:文件,资源名`，语音资源用响应文件 `voice.resources.rsp`（`打包两版.bat:31`）。

编译器是 .NET Framework 4.x 自带版本，代码中未使用 C# 6+ 语法（无 `nameof`、无字符串插值、无 `?.`）——重写时不要假设这里能用新语法来「小修小补」。

## 7. I18n 机制

实现文件 `源码\I18n.cs`，只有一个静态类 `L`：

- `L.T(cn)`：`Enabled == false` 时原样返回；否则查 `Dictionary<string,string>`，查不到**回落中文原文**（`I18n.cs:249-255`）。
- `Enabled` 由编译宏 `OVERSEAS` 决定，默认 `false`（`I18n.cs:9-13`）。**所有打包脚本都没有传 `/define:OVERSEAS`**（`编译.bat`、`打包两版.bat` 均无），所以英文词典是死代码，发布版永远显示中文。
- 词典用 `StringComparer.Ordinal`（`I18n.cs:19`），大小写与全半角敏感。
- 词条 226 条，含大量「界面碎片」——不是标准 i18n（无占位符、无复数规则、无语言文件），而是「整句/片段替换」。很多条目是拼接用的后缀，如 ` 个模组`、` 个文件`、`\r\n` 片段（`I18n.cs:110-129`），这决定了现有文案是**用字符串加法拼出来的**，重写时应改为带占位符的文案模板。

**注意：部分「路径」也走了 `L.T()`**，例如排序目录名 `L.T("排序文件")`（`Core.cs:513`）、备份目录 `L.T("ZOGOS备份")`（`Core.cs:582`）、设置目录 `L.T("ZOGOS创世神启动器")`（`Core.cs:578`）、日志文件名 `L.T("ZOGOS启动器日志.txt")`（`Log.cs:27`）、安装出来的 exe 名 `L.T("Astra创世神协议.exe")`（`Setup.cs:376`）。一旦启用 `OVERSEAS`，这些中文路径会整体变成英文，**旧数据目录将找不到**。这是既有设计缺陷，重写时路径必须与显示文案分离。

`ExitCodes` 的文案同样全部经 `L.T`（`ExitCodes.cs:10-30`、`42-62`），把 Windows 退出码翻译成中文人话；`Explain` 覆盖 `0xC0000005` 等 13 个常见码，`IsCrash` 以 `>= 0x80000000` 判定崩溃（`ExitCodes.cs:34-39`）。

## 8. 给重写者的移植清单

1. **启动参数语义要保留**：`--root/--target/--appdata` 是玩家/客服排障入口，`--shot/--smoke/--susu` 是现有自动化测试入口（截图与布局自检脚本依赖它们，`Program.cs:296-388`）。
2. **设置目录与 ini 键名应保持兼容**：`settings.ini` 的键就是字段名（`Core.cs:864-890`），迁移时可直接读旧文件。
3. **整合包识别算法要原样保留**：打分 + 令牌 + 排序规则（3.1-3.3）决定了老用户升级后能否自动找到包。
4. **便携模式是关键行为**：游戏数据默认写 `Root\UserData`，通过 `-savedatafolder` 传给游戏（`Core.cs:547-566`），不是简单复制 Config。
5. **两版差异只体现在编译期常量**：重写时更合理的是运行期配置 + 授权位，而不是两条构建线。
6. **日志/错误文案里有大量客服话术**（`ExitCodes.Advice`、`Setup` 的失败提示），迁移时容易漏，建议逐条对照附录。

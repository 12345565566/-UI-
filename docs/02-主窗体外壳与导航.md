# 02 · 主窗体外壳、导航与页面骨架

> 分析对象：`源码\MainForm.cs`（2706 行，126 KB）为主，辅以 `Widgets.cs` / `CyberHub.cs` / `CyberTheme.cs` / `Program.cs` / `Edition.cs`。
> 目的：用新技术栈（Web / Qt / Avalonia / Flutter 均可）**1:1 重写外壳**。所有坐标都写成「变量 + 公式 + 魔法数字」，可直接换算成 CSS `left/top/width/height` 或 Flutter `Positioned`。
> 行号格式 `文件:行号`，`MainForm.cs` 简写 `MF`，`Widgets.cs` 简写 `W`。
> 本文只讲外壳与页面骨架；控件内部绘制细节见 03/04，业务逻辑见 05/06。

## 0. 一句话结论

窗口是**一个无边框、固定 1010×650 的自绘画布**：顶上一根 46px 高的自绘页签栏，下面一个 `_body` 容器里叠着 5 个（赞助版 6 个）全屏页面 Panel，每页再放一张距边 16px 的卡片（主页是「左 340 固定 + 右自适应」双栏）。整个布局由**唯一入口 `DoLayout()`** 用一批整数常量算出来，没有任何 Dock/Anchor/TableLayoutPanel——这对重写是好事：坐标公式可以逐条照抄。`MF:755-791`

```
窗口 1010×650（客户区）
├─ ZTabBar       (0, 0, 1010, 46)              自绘标题栏 + 6 页签 + 最小化/关闭
└─ _body         (0, 46, 1010, 604)            透明容器，承载 5~6 个页面
   └─ _pgHome / _pgSort / _pgSet / _pgLog / _pgShare [/ _pgLook]   全部 (0,0,1010,604)
      ├─ 主页:   full=(16,16,978,572)
      │          ├─ _leftCard  (16, 16, 340, 572)      赛博环形启动枢纽
      │          └─ _rightPanel(370, 16, 624, 572)     功能面板（6 按钮 + 10 行信息 + 迷你日志）
      └─ 其余页: 单张卡片 _xxxCard = full = (16,16,978,572)
```

| 步骤 | 做什么 | 位置 |

| 5 | `new MainForm(ctx, st)` → `Application.Run(form)` | `Program.cs:102-103` |

`MainForm` 构造顺序（`MF:110-154`）：

```
设窗口属性 → BuildUi() → new LoadingOverlay（覆盖整个客户区，Visible=false）
→ 启动 50ms 动画定时器 → 订阅 Log.Added / Resize / Move / Load
Resize  → DoLayout() + LoadingOverlay 跟随客户区
Load    → DoLayout() + OnLoaded()
```

`OnLoaded()`（`MF:1014-1052`）是「数据到 UI」的总装：`ReloadSchemes` → `LoadSettingsToUi` → `UpdateAllUi` → `RefreshLogText` → `ApplyBackground` → 首次启动则 `CallSusu(true)` → `UpdateLookUi` → `SwitchPage(0)` → 后台 `ModIndex.StartAsync`，再用一个 700ms 轮询定时器等索引就绪后 `EvaluateSchemes()` 并刷新 UI。

> 重写要点：**UI 构建不依赖数据**，数据全部在 Load/OnLoaded 之后灌进来。新栈里保留这个「先搭骨架、后灌数据」的两段式即可。

`Program` 里还有两个**给你验布局用的现成工具**（可照搬成新版的自检脚本）：

- `SmokeTest(ctx, st, dir)`：无窗口构建 MainForm，反射调用 `OnLoaded`/`DoLayout`/`SwitchPage`，把整棵树 `类型 + Bounds` 转储到 `layout_all.txt`，并在热切换主题后再转储一次（`Program.cs:152-293`）。
- `ShotPages(ctx, st, dir)`：`Show()` 后逐页 `DrawToBitmap` 存 `page_0_home.png … page_5_look.png`，并额外用 `CopyFromScreen` 抓一张真实屏幕截图 `real_home.png`（`Program.cs:296-388`）。注意它还硬编码探测了右面板上两个点的**最上层子控件**（`Program.cs:357-360`，坐标 `(538,27)` 与 `(60,27)`），说明作者当年靠这个查过 z 序遮挡问题。

> 安全提示：本文件所有绘制都在 `try { } catch { }` 里，出错就静默走 `base.OnPaintBackground`。重写时不要模仿这种吞异常，但**要保留「绘制失败不影响交互」**这条设计意图。

## 3. 背景绘制管线 `OnPaintBackground`（`MF:156-177`）

窗体自己画背景，5 步固定顺序（这个顺序非常关键，重写时按同样层次叠）：

```
1. CyberTheme.DrawBackdrop(g, r, _phase, Pal.Accent)      // 渐变 + 3 个呼吸光斑 + 网格（内含第4步）
   ├─ DrawBackdrop 内部末尾又调 DrawGridOverlay            // CyberTheme.cs:84
   └─ 所以网格被画了两遍：一次在光斑后，一次在遮罩后（覆盖在上层）
2. _bgImage  != null → DrawCoverImage(g, _bgImage, r, 1.0f)     // 图片背景（cover 缩放）
3. _videoGif != null → DrawCoverImage(g, _videoGif, r, 1.0f)    // GIF 背景（同一套 cover 逻辑）
4. 图片或 GIF 存在时，盖一层纯色遮罩：
      alpha = clamp(_st.VideoOverlayOpacity, 0, 100) * 2.55      // 默认 38 → alpha≈97
      颜色  rgb(4, 7, 16)
5. CyberTheme.DrawGridOverlay(g, r, _phase, Pal.Accent)          // 网格 + 扫描光带
```

`DrawCoverImage`（`MF:179-198`）就是 CSS `object-fit: cover`：

```
sc = max(r.W / img.W, r.H / img.H)
dw = round(img.W * sc);  dh = round(img.H * sc)
dx = r.X + (r.W - dw) / 2;  dy = r.Y + (r.H - dh) / 2
用 ColorMatrix.Matrix33 = alpha 绘制（本文件恒传 1.0f）
```

### 3.1 背景几何常量（`CyberTheme.cs:30-101`）

| 元素 | 公式 | 魔法数字 |
|---|---|---|
| 底色渐变 | 线性渐变，角度 `35°`，`#040710 → #09122A` | 角度 35 |
| 中心呼吸光 | 圆心 `(w/2, h/2)`，半径 `max(w,h)/2`，`PathGradientBrush` 中心色 = `Alpha(Accent, Pulse(phase,0.9,10,30))`，边缘全透明 | 半径系数 0.5；alpha 10~30；速度 0.9 |
| 品红光斑 | 中心 `x = 0.72w + sin(0.8·phase)·38`，`y = 0.24h + cos(0.6·phase)·24`，半径 `max(80, w/3)`，色 `rgba(255,40,210, Pulse(1.3, 8..28))` | 0.72/0.24、38、24、80、1/3 |
| 绿光斑 | 中心 `x = 0.28w + cos(0.7·phase)·28`，`y = 0.72h + sin(0.9·phase)·26`，半径 `max(70, w/4)`，色 `rgba(0,255,170, Pulse(1.1, 6..22))` | 0.28/0.72、28、26、70、1/4 |
| 网格 | 竖线 `x = (phase·12) % 42` 起，步长 `42`；横线 `y = 0` 起步长 `42`；线色 `rgba(Accent, 18)` | 步长 42、偏移 12/phase |
| 扫描光带 | 高 `52px`，中心 `sy = (phase·46) % h`，竖向渐变 `rgba(Accent,0) → rgba(Accent,42)` | 高 52、偏移 46 |

`Pulse(phase, speed, min, max) = min + (max-min)·(sin(phase·speed)+1)/2`（`CyberTheme.cs:24-28`）。
`_phase` 每 50ms `+0.045`（见 §9）⇒ 正弦周期 `2π/0.045 ≈ 139.6` 帧 ≈ **6.98 秒**；网格每秒右移 `12×0.045×20 ≈ 10.8px`；扫描带每秒下移 `46×0.045×20 ≈ 41.4px`。

> 重写取舍：网格 + 光斑是纯装饰，可用 CSS `repeating-linear-gradient` + 两个 `radial-gradient` 叠 `@keyframes` 平移；`_phase` 可以换成统一的 `--t`（秒）时间轴：`phase = t · 20 · 0.045 = 0.9t`。本文后续所有 `phase` 公式都可用这个换算。

### 4.3 命中与交互（`W:846-899`）

```
Hit(x,y):  _closeRect → -2;  _minRect → -3;  tab[i] → i;  其它 → -1
MouseDown: _pressed = Hit(...)
           若 _pressed == -1（点在空白/标题/图标上）：
               ReleaseCapture + SendMessage(form.Handle, WM_NCLBUTTONDOWN(0xA1), HTCAPTION(0x2))
MouseUp  : 只有 up == _pressed 才触发：
           -2 → CloseClicked → 窗体 Close()
           -3 → MinimizeClicked → WindowState = Minimized
           i≥0 且 i != Selected → Selected = i; Invalidate; TabChanged
```

- **拖动窗口**完全交给系统：空白区域按 `HTCAPTION` 处理（`W:870-878`）。
- **「双击标题」最大化：源码未实现**。全仓库 `grep DoubleClick` 只命中 `PackSwitchForm/ModGraphForm/WorkshopForm` 的列表控件（见 §11）。`HTCAPTION` 下系统是否响应双击取决于窗口样式，本实现未设 `MaximizeBox` 相关逻辑，**未确认**。
- 事件绑定在 `MF:305-307`：`TabChanged → SwitchPage(_tabs.Selected)`、`MinimizeClicked → WindowState=Minimized`、`CloseClicked → Close()`。
- 所有自绘控件都是 `SetStyle(..., Selectable, false)` + `TabStop=false`，**全窗口没有键盘焦点导航**（重写时如果要无障碍，需要补 tab 顺序，这是新增能力，不是还原）。

### 4.4 页签切换 `SwitchPage(int p)`（`MF:990-1003`）

```csharp
_page = p;
_pgHome.Visible = (p==0); _pgSort.Visible = (p==1); _pgSet.Visible = (p==2);
_pgLog.Visible  = (p==3); _pgShare.Visible= (p==4); _pgLook?.Visible = (p==5);
if (_tabs.Selected != p) { _tabs.Selected = p; _tabs.Invalidate(); }   // 反向同步（防递归）
if (p == 1) LayoutCards();          // 排序卡片重排（列表宽度可能变了）
if (p == 3) RefreshLogText();       // 进日志页才读全量日志（Log.TailText(2000)）
if (p == 4) _txtSpec.Text = PackSpec.Text();   // 进分享页才生成格式规范文本
```

> 这是典型的「**懒加载页面数据**」：切页时才做三件事。重写时用路由的 `onEnter` 钩子还原。
> 注意：页面可见性是**6 个 Panel 叠放 + 切 Visible**，不是销毁重建 ⇒ 页面状态（滚动位置、输入框内容）在切页后保留。

## 5. `CyberHub`（环形启动枢纽）——**不在顶栏，而是撑满左卡片**

任务书里写「CyberHub 图标环控件在顶栏的布置」，源码事实是：`CyberHub` 是主页**左卡片**的唯一可见控件，`LayoutLeft` 里 `_hub.Bounds = new Rectangle(0,0,w,h)` 并 `BringToFront()`，把同一张卡片里其它控件全盖住（`MF:797-808`；这些控件在 `MF:398-407` 被显式 `Visible=false`）。重写时它就是「左栏主视觉」，不是导航环。

## 6. `DoLayout()`：唯一的布局入口（`MF:755-791`）

```csharp
int th = 46, pad = 16, gap = 14, cw = 340;                  // ★四个核心魔法数字
if (ClientSize.Width < 100 || ClientSize.Height < 100) return;

_tabs.Bounds  = (0, 0, ClientW, th);
_body.Bounds  = (0, th, ClientW, ClientH - th);
int pageH = _body.Height - pad*2;      // 650-46-32 = 572
int pageW = _body.Width  - pad*2;      // 1010-32    = 978
if (pageH < 100 || pageW < 200) return;

Rectangle full = (pad, pad, pageW, pageH);                  // (16,16,978,572)

_pgHome._pgSort._pgSet._pgLog._pgShare.[_pgLook] .Bounds = (0,0,_body.Width,_body.Height);  // 全部 1010×604

_leftCard.Bounds   = (full.X,             full.Y, cw,              full.Height);  // (16,16,340,572)
_rightPanel.Bounds = (full.X + cw + gap,  full.Y, full.Width-cw-gap, full.Height); // (370,16,624,572)

_sortCard/_setCard/_logCard/_shareCard/[_lookCard].Bounds = full;  // 单卡片页 = (16,16,978,572)

LayoutLeft(); LayoutRight(); LayoutSort(); LayoutSet(); LayoutLog(); LayoutShare();
if (Edition.Sponsor) LayoutLook();
```


**布局触发链**（重写时注意别重入）：

- `Resize` → `DoLayout`（`MF:151`）；`Load` → `DoLayout`（`MF:153`）。
- 每张卡片自己在 `Resize` 事件里调对应 `LayoutXxx`：`_leftCard→LayoutLeft`(324)、`_infoBox→LayoutInfoBox`(345)、`_rightPanel→LayoutRight`(420)、`_sortCard→LayoutSort`(552)、`_sortList→LayoutCards`(564)、`_setCard→LayoutSet`(593)、`_logCard→LayoutLog`(715)、`_shareCard→LayoutShare`(1824)、`_lookCard→LayoutLook`(2129)。
- 所以 `DoLayout` 里设 `Bounds` 会**顺带触发一次**子布局，随后又显式调一遍 ⇒ 每个 `LayoutXxx` 实际跑两次。无害（幂等），但重写时别照抄这种双触发。
- `UpdateAllUi` 在改完 `_showBanner` 后单独再调 `LayoutRight()`（`MF:1128`），因为横幅高度会挤压下面的信息行。

**所有子布局函数的守门尺寸**（不满足就直接 return，控件保持上一次位置）：

## 9. 动画定时器（`MF:132-148`）

```csharp
_animTimer.Interval = 50;            // 20fps
_animTimer.Tick += (s,e) => {
    _phase += 0.045f;                // 每帧相位增量
    if (_hub != null)        { _hub.Phase = _phase;        _hub.Invalidate(); }
    if (_rightPanel != null) { _rightPanel.Phase = _phase; _rightPanel.Invalidate(); }
    if (_tabs != null)       { _tabs.Phase = _phase;       _tabs.Invalidate(); }
};
```

| 项 | 值 |
|---|---|
| 周期 | 50 ms（20 fps） |
| 相位 | `_phase += 0.045`，float，**不取模**（长时间运行精度会掉，但 float 撑几天没问题） |
| 每帧重绘 | 只有 3 个控件：`CyberHub`、`_rightPanel`、`ZTabBar` |
| 窗口本身 | **不重绘** ⇒ 背包背景的光斑/网格只在其它原因触发重绘时"跳"一下（例如窗口移动、页面切换）。这是原实现的省 CPU 手法，也是为什么静态截图里网格位置每次都不同 |
| 关窗清理 | `FormClosed` 里停并 `Dispose` 两个定时器（`MF:148`） |
| 代码注释 | 明确写了「33ms(30fps) 同时重画 3 个控件会让窗口被判未响应，降到 20fps 视觉几乎无差别」 |

另有两个**独立**定时器：

- `_videoTimer`：90 ms，只做 `Invalidate()`（**故意不用 `Invalidate(true)`**，注释：会把所有子控件一起重画，90ms 一次必然卡死），驱动 GIF 背景逐帧（`MF:2409-2419`）。
- `LoadingOverlay` 自带 33 ms 雷达波动画，`Visible && IsHandleCreated && !IsDisposed` 才重绘（`LoadingOverlay.cs:31-39`）。

> 重写建议：把 `phase` 归一成秒 `t`，三个控件的动画改用 `requestAnimationFrame` + CSS/合成层；`phase = 0.9 × t`（因 20fps × 0.045）。

### 明确的两个缺陷（重写时不要复制）

1. **`_loading` 被 Dispose 后没有重建**：`_loading` 是 `Controls` 的直接子控件（`MF:128-130`），`RebuildUi` 会连它一起 Dispose，但函数体内**没有** `new LoadingOverlay()`。之后每次点「启动游戏」都会走 `SetBusy(true)` → `_loading.ShowOverlay(...)`（`MF:1319`），对已释放控件设置 `Visible` 会抛 `ObjectDisposedException`。也就是说：**换过主题后再启动游戏，本应弹的"正在加载"遮罩会抛异常**（被 `Application.ThreadException` 兜住弹错误框）。
2. **`BuildShare()`/`BuildLook()` 与 `BuildUi` 的可见性**：`BuildUi` 里 `BuildShare()` 无条件调用、`BuildLook()` 仅赞助版（`MF:224-242`），而 `_pgShare/_pgLook` 的 `Controls.Add` 顺序是 **log → share → look → set → sort → home**（`MF:234-239`），WinForms 中**后加的在上层**（z 序更靠前）。因为同一时刻只显示一页，这个顺序实际无影响；但重写若用绝对定位叠放，务必按「当前页才 display」处理。

> 更稳的重写路线：主题切换只改一层 CSS 变量 / 一个 Theme 对象，**不重建控件树**。原实现重建是因为 GDI+ 的 `Pal` 是静态全局色，控件构造时就把颜色烤进字段了。

## 14. 重写落地建议（最短路径）

1. **先做 3 个抽象**：`Shell`（1010×650 圆角 12 的窗口 + 背景管线）、`TopBar`（46px，页签数据驱动）、`Page`（6 个，切页只切 `display`）。
2. **网格系统照抄**：`padding:16, gap:14, 左栏 340，右栏 flex:1`，单卡片页 = `inset:16px`。
3. **动画统一一条时间轴**：`phase = 0.9 × seconds`，三个订阅者（hub / rightPanel / topbar）。原实现 20fps，新栈 60fps 只会更顺，`phase` 系数保持不变即可复现节奏。
4. **背景层拆 4 层 div**：渐变+光斑（CSS）、图片/GIF（`object-fit:cover`）、遮罩（`rgba(4,7,16, overlay)`）、网格+扫描带（`repeating-linear-gradient` + 动画）。视频用一层 `<video autoplay muted loop playsinline object-fit:cover>`，**不要再抽 GIF**。
5. **主题不重建树**：把 `Pal` 的 20 个颜色做成 CSS 变量 / Theme 对象，切换时只换变量。这样能顺手消掉 §11 的两个缺陷（尤其 `_loading` 那个会抛异常的）。
6. **验收工具照搬**：按 `Program.cs:296-388` 写一个「逐页截图 + 控件树 Bounds 转储」的脚本，逐项对比本文表格。原项目自己就是靠这个查 z 序和布局的。

> 读者 = 要用新技术栈重写 UI 的人。本册只讲**业务层**：一个界面动作背后到底读什么、写什么、花多久、会抛什么错、返回什么状态。

## 1. 整合包目录约定

### 1.1 标准形态（识别即按这一层判定）

整合包根目录 = **里面同时有 `RimWorld\`、`Config\`、`排序文件\` 的那一层**（`MainForm.cs:1791` 的文案就是这么对玩家解释的）。启动器本身也放在这一层。

| 相对根目录的路径 | 内容 | 谁生成 | 是否必须 |
|---|---|---|---|
| `RimWorld\RimWorldWin64.exe` | 游戏主程序（32 位版是 `RimWorld.exe`） | 整合包作者 | 完整包必须 |
| `RimWorld\Mods\` | 模组文件夹，每个模组一个子目录 | 整合包作者 | 必须（空目录算 problem） |
| `RimWorld\Data\` | 官方 Data（本体模组） | 游戏本体 | 否（存在则一起扫） |
| `RimWorld\Version.txt` | 游戏版本字符串，被当成 `GameVersion` | 整合包作者 | 否（缺失则"未知"） |
| `Config\ModsConfig.xml` | **整合包默认排序**（内置方案） | 整合包作者 | 必须（判"不像整合包"的关键） |
| `Config\*.xml` | 其余默认配置（Prefs、KeyPrefs 等） | 整合包作者 | 否 |
| `排序文件\*.xml` / `*.json` / `*.txt` | 可切换的排序方案 | 整合包作者 | 至少 1 个 |
| `UserData\` | 便携模式的游戏数据根（`-savedatafolder` 指向它） | **启动器首次启动后自动建** | 否 |
| `ZOGOS备份\` | 配置备份 | 启动器 | 否 |
| `ZOGOS整合包标识.json` + `zogos.pack` | 识别令牌（packId） | 启动器写入 | 否（可后补） |
| `rimsort*.exe` + `_internal\` | 配套模组管理器 | 整合包作者 | 规范要求，代码只做检测不强制 |

依据：`Core.cs:509-514`（GameDir/PackConfigDir/SortDir/ModsDir 的拼法）、`Core5.cs:57-122`（`PackSpec.Text()` 里给玩家看的规范全文，含"必需/可选"清单）。

### 1.2 三个"数据目录"必须分清（重写时最容易搞混）

| 概念 | 字段 | 实际值 | 谁读它 |
|---|---|---|---|
| 整合包默认配置 | `PackContext.PackConfigDir` | `<Root>\Config` | 部署时作为**源**整份复制出去 |
| 游戏实际读的配置 | `PackContext.TargetConfigDir` | 默认 `<Root>\UserData\Config` | 部署时作为**目标**被清空+覆盖 |
| 传给游戏的 `-savedatafolder` | `PackContext.SaveDataDir` | `TargetConfigDir` 的**父目录**（默认 `<Root>\UserData`） | `GameLauncher.BuildArguments` |

- 默认目标目录不再写 C 盘 LocalLow（老版本会，`Core.cs:525-534` 已改为优先整合包内 `UserData\Config`）。
- 若 `Settings.TargetConfigDir` 是老的 LocalLow 路径、或以 `\UserData\Config` 结尾（搬家后失效）、或不是以 `Config` 结尾、或全路径 > 210 字符 → **一律回退**到 `<Root>\UserData\Config`，并往 `Notes` 记一条提示（`Core.cs:529-544`、`PathHelp.IsUsableConfigDir` `Core.cs:110`）。
- `PortableData` = `SaveDataDir` 是否落在 `Root` 内（`Core.cs:557-563`）。非便携时 `Notes` 里写明"游戏数据目录在整合包外"。
- 便携且根目录不可写 → **直接算 problem**："整合包目录不可写，便携模式无法创建 UserData"（`Core.cs:567-568`）。

### 1.3 识别逻辑（三层，依次降级）

**第一层：识别令牌**（改文件夹名/换盘符仍能认）
- 文件：`ZOGOS整合包标识.json`（12 位 packId + packName + updatedAt + game + gameExe + configDir + sortDir + gameVersion + sortScheme + modCount + launcher）；副本 `zogos.pack`（纯 packId 一行）。`Core4.cs:16-17`、`Core4.cs:95-142`
- 读：正则抓 `"packId"`，抓不到再读 `zogos.pack` 第一行非空（`Core4.cs:36-61`）
- 写：`PackMarker.Write(root, packId, gameVersion, sortScheme, modCount, out err)`，packId 为空时先读旧的、再没有才 `NewId()`（GUID 前 12 位）。`Core4.cs:95-112`

**第二层：特征打分**（`PackDetector.Score`，`Core4.cs:172-228`）

| 特征 | 加分 | 备注 |
|---|---|---|
| 识别令牌存在 | **+100** | 有 packId 时把 packId 带出 |
| `RimWorld\RimWorldWin64.exe` 或 `RimWorld\RimWorld.exe` | **+40** | |
| `Config\ModsConfig.xml` | **+30** | 只有 `Config\` 目录（无文件）+10 |
| `排序文件\` 里 .xml/.json 数量 > 0 | **+25** | 目录存在但空 +8 |
| `RimWorld\Mods\` | +15 | |
| `RimWorld\Version.txt` | +5 | 不加 notes |

`Strict`（"像整合包"）= `hasExe && (hasCfg || sortN > 0)` —— 光有个 RimWorld 本体不算整合包（`Core4.cs:226`）。

**第三层：搜索顺序**（`PackDetector.ResolveRoot`，`Core4.cs:274-366`，最多 600 个候选 `Core4.cs:170`）
1. 手动指定目录（`rootOverride`）及其 `RimWorld` 子目录、父目录 —— 只要有一个 Strict 就直接采用（`Core4.cs:281-297`）
2. 启动器所在目录 + 其直接子目录（`AddWithChildren`）
3. 上一层目录 + 其子目录
4. 上两层目录
5. `Settings.Root`（上次记住的位置）
6. 先只保留 Strict 候选；`Settings.PackId` 能匹配到某个候选项的 packId → 直接命中
7. 否则排序：**启动器自身所在目录优先** → 分数高 → 路径短（`Core4.cs:337-344`）
8. 兜底：`launcherDir`（并给 Notes 提示去手动绑定）

结果写进 `PackContext.DetectionLog`（字符串，含每个候选的 `Explain()`），`PackContext.Candidates`（候选清单）。多个 Strict 时给一条 Note "发现了 N 个像整合包的目录…"（`Core4.cs:354-358`）。

### 1.4 环境体检（`PackContext.Detect` 顺带做完，`Core.cs:610-663`）

| 检查 | 归类 | 文案 |
|---|---|---|
| 路径含非 ASCII | `NonAscii` + `NonAsciiSample` | 不算 problem，`WarnNonAscii` 时启动前弹窗 |
| 找不到主程序 | **Problem** | 没有找到游戏主程序：`<exe>` |
| 主程序头两字节不是 `MZ` | **Problem** | 不是有效的 Windows 程序（可能 Linux/安卓版或没解压完整）`Core.cs:641-647` |
| 无 `Mods` 目录 | **Problem** | 没有找到模组目录 |
| `Mods` 目录为空 | **Problem** | 模组目录是空的 |
| 无 `Config` 目录 | **Problem** | 没有找到整合包 Config 目录 |
| 既无 `Config\ModsConfig.xml` 又无 `排序文件\*.xml` | **Problem** | 这个目录不像整合包目录…请到【设置】点【绑定整合包文件夹…】 |
| 无 `排序文件` 目录 / 无目标配置目录 | Note（非阻断） | 启动时会自动创建 |
| 首次识别到足够特征但无令牌 | 自动 `PackMarker.Write` | 成功/失败各一条 Note |
| 备份目录不可写 | 回退到 `%LOCALAPPDATA%\ZOGOS创世神启动器\备份` + Note | `Core.cs:582-588` |

`Problems.Count == 0` 即 `PackContext.Ok`（`Core.cs:464`）。**UI 语义**：`!Ok` 时导出被禁止（`MainForm.cs:1952`），启动会先弹"环境有问题，走还是去设置页"（`MainForm.cs:1344-1357`）。

## 2. 数据模型

### 2.1 SortScheme（一份排序方案）`Core.cs:166-385`

| 字段 | 类型 | 含义 | 默认值 |
|---|---|---|---|
| `SourcePath` | string | 方案文件绝对路径 | — |
| `Name` | string | 显示名；内置方案固定为 `L.T("整合包默认排序")`，其余取文件名（不含扩展名） | 文件名 |
| `Format` | string | `"XML"` / `"JSON"` | `"XML"` |
| `Version` | string | `ModsConfig` 里的 `<version>`（游戏版本） | null |
| `IsBuiltIn` | bool | 是否 `Config\ModsConfig.xml` 那份 | false |
| `Modified` | DateTime | 文件最后写入时间 | `DateTime.MinValue` |
| `ParseError` | string | 解析失败原因；`null` = 解析成功 | null |
| `Mods` | List\<string\> | activeMods（保持原顺序，这是排序本体） | 空表 |
| `Expansions` | List\<string\> | knownExpansions | 空表 |
| `HasRjw` | bool | 是否判为成人向（见下） | false |
| `RjwCount` | int | 命中 RJW 特征的模组条数 | 0 |
| `Missing` | int | 本地缺失模组数（由 ModIndex 回填） | 0 |
| `MissingList` | List\<string\> | 缺失的 packageId | 空表 |
| `DefaultExpansions`（static） | List\<string\> | 六个官方 DLC：`ludeon.rimworld` / `.royalty` / `.ideology` / `.biotech` / `.anomaly` / `.odyssey` | 固定 |

派生属性：`FileName`、`ModCountText`（"N 个模组"）、`VersionText`（空则"未知版本"）。

**解析**（`SortScheme.Parse` `Core.cs:209-246`）
- 先 `PathHelp.ReadAllTextSmart`（BOM 感知：UTF-8 BOM / UTF-16 LE / BE；无 BOM 先严格 UTF-8，失败退 GB2312=cp936，再失败退 UTF-8 宽松）`Core.cs:140-160`
- `TrimStart()` 以 `{` 开头 → JSON：用正则+手写扫描器取 `version` / `activeMods` / `knownExpansions`（RimSort 的排序文件格式），**不是真 JSON 解析器**（`Core.cs:284-310`）
- 否则 → `XmlDocument.Load(path)`，取 `root/version`、`root/activeMods/li`、`root/knownExpansions/li`
- 任何异常 → `ParseError = ex.Message`；解析成功但 `Mods.Count == 0` → `ParseError = "文件中没有找到模组列表（activeMods）"`（`Core.cs:243`）

**RJW 判定**（`DetectRjw` `Core.cs:317-341`）——作者明确修过一次误判（注释：以前只要 id 带 rjw 就标，几乎所有包都被标）
- 强信号正则：`(^|[._\-])rjw([._\-]|$)|rimjobworld`
- 弱信号：`sexperience|sexperiments|licentia|brothel`
- 结果：`HasRjw = 方案名含「色色」或 "RJW" || 强信号数 ≥ 2 || (强+弱) ≥ 3`

**写出**（`WriteModsConfig(destPath)` `Core.cs:344-375`）
- 目标目录不存在则创建；`XmlWriterSettings`：缩进 2 空格、UTF-8 **无 BOM**、换行 `\r\n`、带 XML 声明
- 结构：`<ModsConfigData><version>…</version><activeMods><li>…</li></activeMods><knownExpansions>…</knownExpansions></ModsConfigData>`
- `Version` 为空时写死 `"1.7.0"`；`Expansions` 为空时用 `DefaultExpansions`
- **覆盖写**（`XmlWriter.Create`），会抛 `IOException`/`UnauthorizedAccessException`

## 3. 核心流程

### 3.1 排序方案加载与评估

**`SortSchemeLoader.Load(ctx)`** `Core.cs:387-429`
1. 若 `<Root>\Config\ModsConfig.xml` 存在 → 解析为"整合包默认排序"，`IsBuiltIn = true`；**解析出错则不加入列表**（静默丢弃）。
2. 若 `SortDir` 存在 → `Directory.GetFiles` 取全部文件，按文件名 `OrdinalIgnoreCase` 排序，只接受 `.xml/.json/.txt`，逐个 `SortScheme.Parse`，`ParseError != null` 的**跳过并 warn**（`Log.Warn("排序文件无法解析，已跳过: …")`）。
3. 目录读失败 → `Log.Error` 并返回已收集的部分（不抛异常）。

- 耗时：<50ms（常规几十个文件）；磁盘慢/机械盘几百 ms。**同步调用即可**。
- 返回：`List<SortScheme>`，可能为空。

**`ModIndex.StartAsync(gameDir)`** `Core2.cs:30-34` → 线程池异步建索引：递归扫 `RimWorld\Mods` 和 `RimWorld\Data` 下所有 `About.xml`（**深度上限 6 层** `Core2.cs:67`），读 `packageId` 塞进 `HashSet`（大小写不敏感）。完成后 `Ready = true`，日志打印"模组索引完成：本地可用 packageId N 个（耗时 X ms）"。
- 耗时：**几百个模组时秒级**（每个 About.xml 都要 XML 解析）。这就是为什么它是异步的。
- UI 语义：`EvaluateSchemes()` 在 `!ModIndex.Ready` 时**直接不执行**（`MainForm.cs:1194`），所以刚进界面时卡片的"本地缺失 N 个"可能先不显示；索引完成后需要再触发一次评估（`ModIndex.Ready` 变化 → 由调用方重新 Evaluate，见 `ReloadSchemes` 里 `EvaluateSchemes` 的位置）。
- `Contains(id)` 对空 id 返回 **true**（`Core2.cs:26`），即空串不算缺失。

**`ModIndex.Evaluate(scheme)`** `Core2.cs:97-107`：遍历 `scheme.Mods`，不在索引里的塞进 `MissingList`，算 `Missing`。**只是一个提示**——创意工坊模组不在本地 Mods 目录，也会被算进来（源码注释明确这么说）。

**`PickDefaultScheme()`**（UI 层，`MainForm.cs:1200-1214`）优先级：`Settings.LastScheme` 全路径精确匹配 → 第一个 `IsBuiltIn` → 第一个方案 → null。

**`ReloadSchemes(announce)`**（`MainForm.cs:1177-1190`）：Load →（异常则置空）→ Evaluate → 重建卡片 → PickDefault → UpdateAllUi。**全同步**。

### 3.2 部署 `ConfigDeployer.Deploy(ctx, scheme, st, progress)` `Core2.cs:165-330`

> 这是整个应用最危险的一步。`progress` 是 `Action<string>`，源码里直接转成 `BackgroundWorker.ReportProgress` 回 UI 改状态栏文字（`MainForm.cs:1429-1432`），**没有百分比**。

**步骤与副作用（严格按行号）**

| # | 步骤 | 读/写 | 失败处理 |
|---|---|---|---|
| 0 | 参数检查 `ctx`/`scheme` 为 null → `Errors.Add` 并立即返回 | — | 返回失败 |
| 1 | `TargetConfigDir` 不存在则 `CreateDirectory` | 写目录 | 失败 → `Errors` + 返回（`Core2.cs:177-185`） |
| 2 | 判断是否完整部署：`needFull = st==null \|\| st.ReplaceEveryTime \|\| !DeployState.Matches(ctx)` | 读 `.zogos_deploy.ini` | — |
| 3 | `needFull && AutoBackup`（或 `st==null`，默认备份）→ `Backup(TargetConfigDir, BackupDir, "备份", Warnings)` | 复制整个 Config 到 `ZOGOS备份\备份_yyyyMMdd_HHmmss` | **失败即中止**："备份失败，为了保护你的存档，已放弃替换配置"（`Core2.cs:205-209`） |
| 4 | `needFull` 时先把 `Prefs.xml`、`KeyPrefs.xml` 复制到 `%TEMP%\zogos_keep_prefs.xml` / `zogos_keep_keyprefs.xml` | 读+写 temp | 异常吞掉（`catch{}`） |
| 5 | `needFull && ClearConfig` → `FileOps.ClearDir(TargetConfigDir)` | **删空目标目录** | 删除失败转为 `Errors`（路径过长/占用） |
| 6 | `needFull` → `FileOps.CopyTree(PackConfigDir, TargetConfigDir, Errors, skipReadme:true)`；随后把 temp 里的 Prefs/KeyPrefs 覆盖回去 | 读整合包 Config → 写目标 | `PackConfigDir` 不存在 → `Errors.Add` |
| 7 | 非完整部署：把旧 `ModsConfig.xml` 另存为 `ModsConfig.xml.zogos旧版` | 写 | 吞异常 |
| 8 | `scheme.WriteModsConfig(TargetConfigDir\ModsConfig.xml)`，`ModsWritten = scheme.Mods.Count` | 覆盖写 | 失败 → `Errors`（`Core2.cs:271-280`） |
| 9 | `st==null \|\| st.SyncGameConfig` → 若 `RimWorld\Config` 存在：先把它的 ModsConfig 另存 `.zogos备份`（只存一次），再写入同一份方案 | 写游戏目录内 Config | 失败 → **只加 Warning**，不影响启动 |
| 10 | `PruneBackups(BackupDir, KeepBackups)`：按目录 LastWriteTime 降序，保留前 keep 份，其余 `Delete(true)` | 删旧备份 | 单条失败吞掉 |
| 11 | 校验：重新 `SortScheme.Parse` 目标 `ModsConfig.xml`，模组数与预期不符 → Warning | 读回 | 文件不存在 → `Errors.Add` |
| 12 | `if (r.Success) DeployState.Save(ctx)` | 写 `.zogos_deploy.ini` | — |

**"只更新排序、不动玩家设置"的机制**（重写必须保留）
- `DeployState.Matches` 为真 → 只做第 8/9 步，玩家改过的画面/按键/模组设置全部保留。
- 判断依据（`Core6.cs:42-78`）：读 `.zogos_deploy.ini` 的 `packId` 与 `sig`；两边都有 packId 且不一致 → 不匹配；`sig` 能算出来就比指纹；**都算不出但记录文件在 → 认为已部署**（避免拿不到 packId 就每次重置）。
- `sig` = 整合包 Config 的轻量指纹 `文件数-总字节-最大LastWriteTimeUtc.Ticks-文件名长度和`（`Core6.cs:22-40`）。
- `DeployState.Reset(ctx)` 删掉这个文件 → 下次启动完整重置（`Core6.cs:98`，UI 在 `MainForm.cs:687` 调）。

- **耗时**：非完整部署 < 100ms；完整部署取决于 Config 体积，通常几百 ms ~ 数秒（只复制 Config，不动 Mods）。**必须异步**（源码用 BackgroundWorker）。
- **可抛出的异常**：`UnauthorizedAccessException`（目标只读/Program Files）、`PathTooLongException`（被 `FileOps` 内部消化成计数 + 错误文案）、`IOException`（文件占用，比如游戏还开着）。
- **错误文案特征**：`FileOps.CopyTree/ClearDir` 把失败聚合成两条中文："有 N 个文件因路径过长被跳过（Windows 上限 260 字符）。把整合包或目标配置目录换成更短的路径即可。" / "有 N 个文件复制失败，首个错误：…"（`Core.cs:935-1004`）。

**`GameLauncher.Validate` 判定**（`Core3.cs:11-42`）
- exe 不存在 → 失败
- `FileInfo.Length < 65536` → "文件不完整（正常应该是 200 KB 左右）"
- 头两字节非 `MZ`，并按 `0x7F 0x45`→"这是 Linux 程序"、`0x50 0x4B`→"这是个压缩包" 给出额外说明

**`GameLauncher.BuildArguments`**（`Core3.cs:45-54`）：只有 `-savedatafolder="<SaveDataDir>"`，参数里的引号被转义。

**`GameLauncher.Start`**（`Core3.cs:56-68`）：`UseShellExecute=false`、`WorkingDirectory=GameDir`，启动后写日志（含 PID / 工作目录 / 参数）。

**`MonitorProcess`**（`MainForm.cs:1525-1565`）：线程池 `WaitForExit(180000)`（**只等 3 分钟**，超时直接放弃监视、不改 UI），退出后读 `ExitCode`：
- `!= 0` → 按钮副标题"上次启动崩溃了" + 弹窗 `ShowLaunchError`，内容含十六进制码、`ExitCodes.Explain(code)`、`ExitCodes.Advice(code)`
- `== 0` → 按钮副标题"游戏已关闭"
- 注意：进程未在 3 分钟内退出 → **没有任何 UI 反馈**，这是现状，重写建议改成真实进程监视（`Process.Exited` 事件 / 无限等待）。

### 3.4 备份与还原

**备份**（`ConfigDeployer.Backup` `Core2.cs:134-163`）
- 目标目录 `backupRoot\label_yyyyMMdd_HHmmss`，重名则追加 `_1`、`_2`…
- `FileOps.CopyTree` 递归复制（`skipReadme=false`），返回文件数
- 在备份目录里写 `备份说明.txt`（UTF-8 BOM）：备份时间 / 源目录 / 文件数量 / "还原方法：打开启动器「设置」页，点「从备份还原」，选择本文件夹。"
- 复制失败不抛异常，只把错误文案并入 `warnings`

**还原**（`ConfigDeployer.Restore(backupDir, targetDir)` `Core2.cs:357-378`）
1. 校验备份目录存在、创建目标目录
2. **先把当前目标配置再备份一次**到 `<targetDir 父目录>\ZOGOS还原前备份\还原前备份_<stamp>`（失败吞掉）
3. `ClearDir(targetDir)` → `CopyTree(backupDir, targetDir, skipReadme:true)`（跳过 `备份说明.txt`）
4. 返回 `DeployResult`（`Copied`/`Removed`/`Warnings`/`Errors`）

- UI：`RestoreFromBackup()`（`MainForm.cs:1708-1750`）先用 `ListBackups` 列出（按时间降序），`FolderBrowserDialog` 默认指最新的，二次确认后同步执行还原（**同步阻塞 UI**，Config 小时可接受），完成弹窗报"复制文件数 + 前 10 条错误"。
- **注意**：还原会覆盖 `ModsConfig.xml`，但**不会**调用 `DeployState.Save`，所以下次启动仍会按当前方案再写一次排序（这个行为与作者意图一致：还原的是"配置现场"，排序以当前选择为准）。

### 3.5 导出整合包 `PackExporter.Export(ctx, scheme, full, outZip, log, prog)` `Core5.cs:295-384`

**入参**：`full` = 完整包（含 `RimWorld\`）或轻量包（只 Config + 排序 + 令牌）。
**回调**：`log(string)` 给状态栏，`prog(i, n, relPath)` 给逐文件进度（**有确定进度**，可直接做进度条）。

流程：
1. `PackMarker.Write(ctx.Root, null, …)` 刷新令牌；失败但已有旧令牌 → Warning 继续；无令牌 → **Error 中止**（`Core5.cs:301-315`）
2. `CollectFiles` 迭代遍历（显式 `Stack<string>`，非递归）收集文件，跳过规则见下表；`RawBytes` = 总字节
3. 检查有没有 `rimsort*.exe`，没有 → Warning（"导出的包会缺少配套工具"）
4. 文件数为 0 → Error 中止
5. 建 zip：先写 `<包名>/ZOGOS整合包说明.txt`（`BuildReadme` 生成），再逐文件 `CreateEntryFromFile`，单个失败只 Warning 不中止
6. `Files = 收集数 + 1`，`ZipBytes = 成品大小`

**排除规则**（`Core5.cs:144-187`）

| 规则 | 内容 |
|---|---|
| 永不打包的一级目录 | `ZOGOS备份`、`UserData`、`.git`、`.svn`、`__pycache__`、`$RECYCLE.BIN`、`System Volume Information` |
| 轻量包额外排除 | 一级目录 `RimWorld` |
| 永远排除 | `RimWorld\Logs*`、`RimWorld\Crashes*`、正在导出的那个 zip 自身 |
| 压缩级别 | 已压缩扩展名（`.zip .7z .rar .png .jpg .jpeg .gif .webp .mp4 .mkv .mp3 .ogg .wav .gz .xz .zst .br`）用 `NoCompression`，其余 `Optimal` |

**包名建议**：`ZOGOS_<包名>_<模组数>mods_RimWorld<版本>_<完整|轻量>_<yyyyMMdd>.zip`（`PackSpec.SuggestName` `Core5.cs:49-55`）。包名清洗：非法文件名字符换 `_`、去首尾点和空格、空则"整合包"、截断 40 字符（`Core5.cs:23-40`）。

- **耗时**：完整包几个 GB，**几分钟**；轻量包秒级。必须 BackgroundWorker（源码 `MainForm.cs:1977-2018`，状态栏逐文件刷新）。
- **可能失败**：目标盘空间不足（`IOException`）→ 被外层 catch 抓成 `Errors`；token 目录只读。

### 3.6 导入整合包

**检查**（`PackImporter.Inspect(zip)` `Core5.cs:437-513`）
- 只读扫 zip 条目，`RawBytes` 累加 `Entry.Length`；识别令牌、Config、主程序、排序文件、Mods、RimSort

### 4.2 排序图构造（重写时必须复刻的语义）

**加边顺序**（`ModAnalyzer.cs:394-441`）
1. 每个激活模组 `i`：`LoadBefore`（`i → target`）、`LoadAfter`（`target → i`）、`ForceLoadBefore`、`ForceLoadAfter` —— 目标不在激活列表就忽略
2. 依赖边：`dep → i`（Hard 依赖，强制前置在本体之前），**即使没有 loadAfter 也加**
3. 官方 DLC 顺序边：`ludeon.rimworld → royalty → ideology → biotech → anomaly → odyssey`，只连激活列表里存在的相邻项（`ModAnalyzer.cs:489-501`）
4. 边去重：`HashSet` 存 `"from>to"`，同一条边只加一次；`from == to` 忽略

**稳定拓扑排序**（`StableTopo` `ModAnalyzer.cs:503-540`）：每一轮把当前入度为 0 的节点**按下标排序取最小的**，保证结果稳定（同样的输入永远同样的输出）；成环返回 null。

**生成新方案**（`WriteScheme` `ModAnalyzer.cs:602-629`）
- 输出到 `SortDir`（或 `<Root>\排序文件`），文件名 `智能排序_yyyyMMdd_HHmmss.xml` / `安全排序_yyyyMMdd_HHmmss.xml`
- 版本/Expansions 沿用基础方案，Mods 用新顺序（空则用原顺序）
- **同时写一份同名 `.txt` 报告**（`BuildReport`），UTF-8 BOM
- 失败返回 null 并 `Log.Error`（UI 会弹"生成新排序失败，详见日志"）

> 重写提示：`MovedCount` 用的是"同下标 id 不同"的朴素算法，跟真正的 LCS/编辑距离无关，数值只能当粗略指标。

| 3 | `https://cdn.jsdelivr.net/gh/shitaitai/zogos-packs@main/packs.json` | 最快但分支缓存最长 12 小时，故放最后 |

- 默认封面：`cdn.jsdelivr.net/gh/shitaitai/zogos-packs@main/covers/default.jpg`，失败退 `raw.githubusercontent.com` 同路径（`PackFeed.cs:51-65`）
- `FetchPublic(out err, out usedUrl)`：依次试 4 个源，第一个解析出非空列表的就返回；全失败把每个源的错误用 `；` 拼成 `err`
- `IsKnownSource(url)`：去掉 query 后与 4 个内置源逐一比（大小写不敏感）→ 决定走"多源降级"还是"死磕用户填的那一个"（`PackFeedForm.cs:375-380`）
- 每个请求：`Timeout / ReadWriteTimeout = 20000ms`，`UserAgent = "Mozilla/5.0 ZOGOS-Launcher/<版本>"`，`Accept: text/csv,text/plain,application/json,*/*`，强制 `Tls12`（`PackFeed.cs:220-231`）
- **SPA 识别**：响应前 400 字符含 `<html` 或 `<!doctype` 且解析不出数据 → 错误文案"数据源返回的是网页（表格由 JS 加载），程序拿不到内容。请改用静态 CSV/JSON 直链，或点「导入表格」。"（`PackFeed.cs:236-246`）

### 8.2 解析 `ParseTable` `PackFeed.cs:257-345`

- 去 BOM/空白后以 `[` 或 `{` 开头 → 走 `ParseJson`（`JavaScriptSerializer`，`MaxJsonLength = 32MB`，键名兼容 `Name/name/名称` 等多别名，见 `PackFeed.cs:406-419`）
- 否则定分隔符：**第一行里逗号多于 TAB → 逗号，否则 TAB**
- `SplitRows`：支持双引号包裹（字段内可含分隔符/换行，`""` 转义为一个 `"`），`\r` 直接丢弃
- 表头定位：前 5 行里找第一个含「整合包」或「名称」的单元格所在行
- 列映射（按表头关键字；认不出就用固定列序）：

| 目标字段 | 表头关键字 | 固定列序默认 |
|---|---|---|
| Name | 名称 | 0 |
| ModCount | `MOD` / 模组数 | 1 |
| GameVersion | 游戏版 / 本体版本 / 版本 | 2 |
| CopyCount | 副本 | 3 |
| Storytellers | 讲述 | 4 |
| LoadTime | 加载 | 5 |
| MaxFps | `fps`/`FPS` | 6 |
| Rjw | `RJW` | 7 |
| ZipSize | 压缩包 / 压缩 | 8 |
| UnzippedSize | 解压 | 9 |
| QuarkUrl | 夸克 | 10 |
| XunleiUrl | 迅雷 | 11 |
| Description | 简介 / 介绍 | 12 |
| Cover | 封面 / 预览 | **18** |

- 空名字行丢弃；名字里含"整合包名称"的行丢弃（表头重复行）
- **坑**：`Cover` 固定列默认是 18，而 CSV 只有 14 列时取不到 → 空值（安全）；表头里没有"封面"列时封面全空，靠默认图兜底。

### 8.3 本地缓存 `PackFeed.cs:83-150`

| 文件 | 位置 | 格式 |
|---|---|---|
| `packfeed_cache.txt` | `%LOCALAPPDATA%\ZOGOS创世神启动器\` | 一行一个包，TAB 分隔 **14 列**（顺序同 PackItem 字段顺序），UTF-8 无 BOM；转义 `\\` `\t` `\n` |
| `packfeed_meta.txt` | 同上 | 第 1 行 = 缓存时间，第 2 行 = 数据源 URL |
| `packcovers\*.img` | 同上 | 封面图，文件名为 `Math.Abs(url.GetHashCode()).ToString("X8") + ".img"`（**注意：.NET 字符串哈希在不同进程/版本间不稳定，跨版本可能失效**） |

- 写缓存时机：在线获取成功、或手动导入表格（source 记"手动导入"）
- 读缓存：列数 < 14 的行跳过；`Name` 空跳过

### 8.5 提交整合包 `PackSubmit.Build` `PackSubmit.cs:47-177`

**为什么不是直接上传**（作者注释 `PackSubmit.cs:10-16`）：普通用户没有仓库写权限，所以"本地生成 zip + 打开预填好的 Issue 页面，让用户把 zip 拖进 Issue"。

**生成物**：`%LOCALAPPDATA%\ZOGOS创世神启动器\submissions\提交_<包名>_yyyyMMdd_HHmmss.zip`，内含：

| 条目 | 内容 |
|---|---|
| `提交信息.txt` | 包名 / 游戏版本 / 模组数量 / 打包时间 / 整合包路径 / 联系方式 / 补充说明 |
| `Config\*.xml` | 来自 `TargetConfigDir`（不存在则退 `PackConfigDir`）的**所有 xml**，**排除 `Prefs.xml`**（玩家个人设置不外传） |
| `Config\ModsConfig.xml` | 当上面两个目录都不存在时，直接从找到的 ModsConfig 复制一份 |
| `模组清单.txt` | 头部注释 + `1. id` 列表（加载顺序） |

- ModsConfig 查找优先级：`TargetConfigDir\ModsConfig.xml` → `PackConfigDir\…` → `GameConfigDir\…` → `LocalLow\…\Config\ModsConfig.xml`（`PackSubmit.cs:60-69`）
- 返回 `Result`：`ZipPath`、`Title`（`【整合包提交】包名 · 版本 · N 模组`）、`Body`（Markdown 表格 + 说明 + "把 zip 拖进来"）、`IssueUrl`（`https://github.com/shitaitai/zogos-packs/issues/new?title=…&body=…`，URL 编码）、`ModCount`、`Files`
- UI 后续（`PackFeedForm.cs:701-729`）：弹窗告知 → `explorer /select,<zip>` 定位文件 → 用户点确定则打开 Issue 页，打不开就把 Body 复制到剪贴板
- **异常**：任何异常 → `err = ex.Message`、返回 null（UI 弹"生成失败：…"）

## 11. 未确认 / 重写建议

**未确认**（源码本册范围内读不出来，需结合 02/05 号文档或实测）
1. `ModGraphControl` / `ModGraphForm` 里节点勾选（`ModGraphNode.Enabled`）如何驱动重新排序与"安全排序"的排除逻辑 —— 不在本册文件范围。
2. 导出时是否有磁盘剩余空间预检查：`PackExporter` 里**没有**，是否有其它入口做 → 未确认。
3. 导入解压是否会覆盖已存在的同名文件：会（`ExtractToFile(target, overwrite: true)` `Core5.cs:548`），但**没有**冲突提示或"是否覆盖"询问 —— 行为确认，UI 缺提示。
4. `ModIndex.StartAsync` 完成后 UI 是否自动重新 `EvaluateSchemes` —— `MainForm.cs` 里未见 `Ready` 回调，可能靠定时器或下次页面切换，未确认。
5. `PackFeed` 封面文件名用 `string.GetHashCode()`，跨 .NET 版本/进程不稳定 → 缓存可能一直不命中；这是**已确认的缺陷**，重写请改 SHA1/MD5。

**建议在新前端里改掉的（不改变对外行为，只补体验）**
- 所有磁盘密集动作统一成"可取消的异步任务 + 确定进度 + 失败清单"，`Deploy` 与 `Switch` 至少要给阶段文本（源码只给文本，没有百分比）。
- `MonitorProcess` 的 180 秒硬超时改成真实 `Process.Exited` 事件，避免玩家玩两小时回来看到"游戏运行中"却永远没有退出结果。
- `ModAnalyzer.Analyze` 与 `ScanInstalled` 结果加缓存（同一次会话内按 `modsDir` + 最后修改时间），因为启动、体检页、依赖图、分类器会重复扫盘 3~4 次。
- `PackNameZh` / `Classify` 的 AI 调用加"全局并发 1 + 可取消 + 超时提示"，当前是同步阻塞在 UI 线程上的（调用方是否异步取决于各 Form）。
- `ModGraph` 的边补上 `LoadBefore` / `ForceLoad*`，让"图"和"体检报告"一致；孤立依赖（`Hard` 边指向方案外的 id）建议单独画成虚线或列表提示。
